

1. C语言宏定义后面的UL等

   U表示unsigned无符号，例如100U表示这是一个无符号整数。
   L表示long长整数，例如100L表示这是一个长整数。
   UL表示unsigned long无符号长整数，例如100UL表示这是一个无符号长整数。

   在C语言中，除了U、L、UL等后缀外，还有其他一些后缀可以用来指定数据类型：

   F或f：表示该常数是float类型的浮点数。例如，#define PI 3.14F，这里的PI就是一个float类型的浮点数。
   L或l：当用于浮点数时，表示该常数是long double类型的浮点数。例如，#define PI 3.14L，这里的PI就是一个long double类型的浮点数。
   如果浮点数没有后缀，则默认为double类型。

15. 类成员变量，在构造函数前初始化变量

      下面两种写法的区别
       写法一 （不ok， 但容易理解）
       spim_basic::spim_basic(const nrfx_spim_t * p_instance)
       {
       spim_instance = p_instance;
       }

       写法二 （推荐）
       spim_basic::spim_basic(const nrfx_spim_t * p_instance )
       : spim_instance(p_instance)
       {
       }

       举个通俗的例子
       写法一：就像买了个空水杯，先倒满白开水（默认初始化），然后再倒掉，重新倒上可乐（赋值）。
       写法二：就像直接跟老板说“给我来一杯装好可乐的杯子”（初始化）。

       写法一：构造函数体内赋值**
       先对 `spim_instance` 执行**默认初始化**，再执行 `operator=` 赋值。

       写法二：初始化列表初始化**
       直接用 `p_instance` 去**构造** `spim_instance`，只一步。

       ---

       情况 1：spim_instance 是普通指针 `const nrfx_spim_t* spim_instance;`

         最终运行结果**数值上一样**，但是流程不同：
         写法一流程：

         1. 进入构造函数前：`spim_instance` 默认初始化（野指针！随机值）
         2. 进到 `{}` 内部：`spim_instance = p_instance;` 覆盖指针值

         写法二流程：
         1. 构造函数 `{}` 之前：直接 `spim_instance(p_instance)`，指针直接被初始化为入参，**不存在野指针中间状态**
            嵌入式非常看重这点：初始化列表没有中间野值，更安全。

        情况 2：spim_instance 是引用 /const 成员
         写法一 **编译报错**！引用、`const` 成员**必须在初始化列表初始化，不能在函数体内赋值**
         写法二 正常编译

        情况 3：spim_instance 是自定义类对象（有构造函数）
         写法一：
             1. 先调用 `spim_instance` 的**无参默认构造**
             2. 再调用赋值运算符 `operator=`

         写法二：
             1. 直接调用 `spim_instance( p_instance )` 匹配的构造函数（拷贝构造 / 带参构造）
                少一次构造开销，MCU C++ 里优先选这个。

18. 原子操作怎么实现  //以nrf52来说明

      1). 传统读改写（C语言）为什么会翻车？
         假如你想把变量 X 从 0 改成 1，C 语言底层分三步：

         。把 X 读到寄存器（LDR R0, [X]） -> R0 变成 0。
         。寄存器加 1（ADD R0, #1） -> R0 变成 1。
         。把寄存器写回内存（STR R0, [X]） -> 内存里的 X 变成 1。

         翻车点：如果在第1步和第3步之间，突然来了个中断，把X改成了2。等你中断回来，第3步一写，X就被覆盖成了1，中断里改的2就丢了。

      2). LDREX / STREX 是怎么救场的？
         Cortex-M 的 CPU 里有个隐藏的硬件标记位（叫独占标记）。

         LDREX R0, [X]（独占读）：
         CPU 把 X 的值读进 R0，同时，把这个 X 的内存地址标记为“被我独占盯上了”。

         执行中间的计算逻辑（比如 ADD R0, #1）。

         STREX R1, R0, [X]（独占写）：
         CPU 准备把 R0 写回 X 时，会先检查一下：“这个地址的独占标记还在吗？”

         如果还在（说明中间没有其他中断或别的核碰过这个地址）：写入成功，返回 0。

         如果不在了（说明刚才有中断或者别的代码强行操作了这个地址，破坏了独占标记）：拒绝写入！返回 1，并且不修改内存！

      3). C语言的 __atomic 是怎么用这两条指令的？
         当你写 __atomic_compare_exchange_n（CAS）时，编译器会把它翻译成类似这样的死循环：

         do {
             // 1. 独占读（标记内存）
             old_val = LDREX(&X);
             
             // 2. 检查条件
             if (old_val != expected_val) {
                 break; // 条件不满足，直接退出
             }
             
             // 3. 独占写（尝试写入新值，如果中途被打断会返回 1）
             result = STREX(&X, new_val);
             
         } while (result != 0); // 如果被打断了，重试！

      4). 如果发生中断，具体是怎么处理的？
         假设你正在执行上面这套逻辑：

         你刚执行完 LDREX（标记了内存）。

         突然来了个中断。

         中断处理函数里，碰巧也修改了这个变量 X。

         当中断里的写操作发生时，CPU 会自动清除掉你刚刚标记的独占状态。

         中断退出，你执行 STREX，CPU 一看：“标记没了，不能写！”于是 STREX 返回 1。

         你发现返回 1，立刻 while 循环重来一遍，重新读最新的值，重新算。



19.  关于空宏的详细解释

         #define USBD_PROFILE_CALL_VOID(EventId)

         //通常配套 `#ifdef`
         #ifdef USBD_PROFILE_ENABLE_EVENT
         #define USBD_PROFILE_CALL_VOID(EventId)  usbd_profile_event_handler(EventId)
         #else
         #define USBD_PROFILE_CALL_VOID(EventId)  // 空，不调用
         #endif

         这个宏是封装 USB Profile 层的**void 型事件派发**，方便开启 / 关闭 USB 事件回调，不用到处注释代码。


         // 宏完整定义
         #ifdef USBD_PROFILE_ENABLE_EVENT
         #define USBD_PROFILE_CALL_VOID(EventId) \
             do { \
                 if (usbd_profile_event_handler != NULL) { \
                     usbd_profile_event_handler((uint32_t)(EventId)); \
                 } \
             } while(0)
         #else
         #define USBD_PROFILE_CALL_VOID(EventId)
         #endif
